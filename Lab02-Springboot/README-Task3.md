### 1. Schema and data

```sql
CREATE TABLE product (
    id    BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name  VARCHAR(80)   NOT NULL UNIQUE,
    price DECIMAL(10,2),
    stock INT CHECK (stock >= 0)
);
```

`data.sql` adds Keyboard, Mouse, Monitor, USB cable and Headset. H2 is an embedded in-memory database, so Spring Boot runs both scripts automatically at startup. No `spring.sql.init.mode` is needed. `application.properties` sets `spring.datasource.url=jdbc:h2:mem:shopdb` and enables the H2 console at `/h2-console`.

### 2. Raw JDBC vs JdbcClient

Raw JDBC `findAll()`: **18 lines**. We open the connection, prepare the statement, loop over the `ResultSet`, read every column by name, close everything with try-with-resources and convert the checked `SQLException`:

```java
try (Connection con = dataSource.getConnection();
     PreparedStatement ps = con.prepareStatement(sql);
     ResultSet rs = ps.executeQuery()) {
    List<Product> products = new ArrayList<>();
    while (rs.next()) {
        products.add(new Product(rs.getLong("id"), rs.getString("name"),
                                 rs.getBigDecimal("price"), rs.getInt("stock")));
    }
    return products;
} catch (SQLException e) {
    throw new IllegalStateException("findAll failed", e);
}
```

`JdbcClient` `findAll()`: **4 lines**. Spring gets and releases the connection, and it maps the columns to the record components by name:

```java
return jdbc.sql("SELECT id, name, price, stock FROM product ORDER BY id")
           .query(Product.class).list();
```

`ProductRepository` also has `findById` (returns `Optional`), `findByNameContaining`, `insert` (returns the generated id), `updateStock` and `delete`. **Every value is a bound parameter** (`:id`, `:delta`, `:pattern`…), and no SQL is built by joining strings, so SQL injection is impossible.

`updateStock` only changes the row if the stock stays at 0 or above:

```sql
UPDATE product SET stock = stock + :delta WHERE id = :id AND stock + :delta >= 0
```

It returns the number of changed rows, so **0** means "product not found or not enough stock".

### 3. `@Transactional` restock

```java
@Transactional
public void restock(long fromId, long toId, int qty) {
    if (repo.updateStock(fromId, -qty) == 0) throw new IllegalStateException("not enough stock in product " + fromId);
    if (repo.updateStock(toId, qty) == 0)    throw new IllegalStateException("product " + toId + " not found");
}
```

Two UPDATE statements form one unit of work. Spring wraps the service in a proxy. The proxy starts a transaction before the method, commits if it returns normally, and **rolls back** if it throws a `RuntimeException`. `@Transactional` is on the service, not on the repository or a controller.

### 5. Duplicate name: exception translation

Inserting a second product called `Keyboard` breaks the `UNIQUE` constraint. The test `duplicateNameIsTranslatedToDuplicateKeyException` prints:

```
DUPLICATE -> org.springframework.dao.DuplicateKeyException
  cause   -> org.h2.jdbc.JdbcSQLIntegrityConstraintViolationException
```

The H2 driver throws its own `JdbcSQLIntegrityConstraintViolationException`, which is a checked `SQLException`. Our code never sees it directly. Spring's **exception translator** reads the SQL error code and turns it into `DuplicateKeyException`, an unchecked subclass of `DataAccessException`. This happens inside `JdbcClient`/`JdbcTemplate` when the statement fails, and the `@Repository` annotation also adds a translating proxy for repositories that use plain JDBC or JPA. The benefit is that services can catch one Spring exception type, and that type stays the same if we switch from H2 to PostgreSQL or MySQL.

### 6. Running on PostgreSQL in Docker (profile `prod`)

The tests and the normal run still use H2, so `./mvnw verify` needs no database and no environment variables. With the `prod` profile the same code runs on PostgreSQL 16 in Docker (container `shop-db`, port 5433, database `shop`, user `postgres`).

- `pom.xml`: added the `org.postgresql:postgresql` driver (runtime).
- `application-prod.properties`: the URL `jdbc:postgresql://localhost:5433/shop`, the user `${DB_USER:postgres}` and the password `${DB_PASSWORD}`. **The password is read from an environment variable and is never committed.** `spring.sql.init.mode=always` is needed because Spring Boot only runs `schema.sql`/`data.sql` automatically for embedded databases like H2.
- `schema.sql` uses `CREATE TABLE IF NOT EXISTS` so a restart doesn't fail on the existing table. Postgres keeps its data, unlike in-memory H2.
- `data-postgres.sql` is the same 5 inserts with `ON CONFLICT (name) DO NOTHING`, so a restart doesn't insert duplicates.
- `docker-compose.yml` (in `shop/`) describes the same container for whoever clones the repo.
- `.env` holds the real `DB_USER`/`DB_PASSWORD` and is in `.gitignore`. `.env.example` is the committed template with a fake password. Spring reads `.env` through `spring.config.import=optional:file:.env[.properties]`, and `docker compose` reads it automatically.
